# v5.0.0 Release Notes

**Release Date:** 2026-03-13
**Release Type:** Major
**Previous Version:** 4.6.1 (FloydDeployable sandbox)

---

## Summary

v5.0.0 is the first release from the new unified production directory (`/Volumes/Storage/floyd/`). It consolidates the scattered Floyd/SuperFloyd ecosystem into a single, clean, production-grade home with proper versioning, document management, split templates, and unified extensibility management. All known degradation triggers from the sandbox have been removed or corrected.

---

## Changes

### Features
- **Split templates**: `floyd-general.md.tpl` (general enterprise) and `superfloyd-coder.md.tpl` (coding-only) replacing the single `coder.md.tpl`
- **Deterministic Prompt Framework**: 20-template framework integrated at `internal/agent/templates/deterministic/`
- **Paranoia module**: Runtime integrity checks (`internal/paranoia/paranoia.go`) — NaN propagation, atomic consistency, negative-zero trap
- **SuperFloyd resilience**: Safety systems (`internal/cmd/superfloyd_resilience.go`) — quality gates, circuit breaker, consistency lock, auto-stabilize
- **Extensibility directory**: Unified `extensibility/{skills,agents,plugins}` with 34 agent personas migrated
- **Binary identity**: `superfloyd --version` now correctly reports `superfloyd version v5.0.0`
- **Versioning infrastructure**: `scripts/{build,release,version-bump,validate-release}.sh`
- **Document management**: 5 document templates, organized `docs/{architecture,guides,reference,specifications,decisions,releases}`

### Improvements
- Context window correctly set to `204800` tokens (GLM-5 spec)
- Token count reset (`PromptTokens = 0`) after summarization — prevents phantom token accumulation
- Summarization threshold uses `remaining <= threshold` — triggers correctly at context pressure
- Phantom MCP server references removed from templates (`context-singularity-v2`, `omega-v2`, `hivemind-v2`, `pattern-crystallizer-v2`)
- Empty degradation trigger headers removed (`DEGRADED MODE PLAYBOOK`, `SHADOW DAEMON & HANDOFF PROTOCOL`)

### Fixes
- Import path `context` removed from `internal/agent/tools/registry.go` (unused import build error)
- `version.BinaryName` variable added and wired to `--version` output

### Breaking Changes
- **Directory**: Production root is now `/Volumes/Storage/floyd/` (not `/Volumes/Storage/floyd-sandbox/FloydDeployable/`)
- **Module path**: `github.com/legacy-ai/floyd` (was `github.com/CaptainPhantasy/FloydSandyIso`)
- **Template names**: `floyd-general.md.tpl` and `superfloyd-coder.md.tpl` are the new primary templates

---

## Upgrade Guide

### From FloydDeployable (v4.6.1)

1. Use binaries from `/Volumes/Storage/floyd/floyd` and `/Volumes/Storage/floyd/superfloyd`
2. Point `floyd.json` `working_dir` to your project (unchanged)
3. Skills/agents from `~/.config/floyd/` continue to work alongside new `extensibility/` directory

### Configuration Changes

No config schema changes. `floyd.json` from floyd-main is the base — context window already at 204800.
